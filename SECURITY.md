# Security Policy

Please do not publish device identifiers, raw logs, unpublished vulnerability details, vendor binaries, credentials, keys, or exploit-ready reproduction steps in a public issue.

Before the repository is made public, configure a private security contact or GitHub private vulnerability reporting and replace this paragraph with that exact route. Until then, keep security reports private and include only the minimum reproduction information needed to assess impact.

Reports should state the affected model and firmware, authorization to test, observed impact, whether the behavior survives reboot, and a minimal non-destructive proof. Remove serial numbers, account details, local paths, photos and unrelated logs.

Public disclosure should follow the affected vendor's current coordinated disclosure process and any applicable legal or contractual requirements.
