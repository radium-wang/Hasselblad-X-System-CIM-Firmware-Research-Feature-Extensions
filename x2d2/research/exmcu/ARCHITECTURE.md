# X2D II 1.3.18.1：肩屏与 exMCU 架构

## 适用范围与结论

2026-10-31 静态核查。输入为原厂 `exMCU_hb722.cont`、主机 `msg2dbus` 和初始化配置；身份见[证据摘要](evidence-summary.json)。未访问设备或执行原厂测试程序。

**肩屏由独立 exMCU 管理，MCU 本地运行界面、绘制参数。** 固件包含 STM32L4xx HAL、FreeRTOS ARM_CM4F、LCDController、GuiExec、Qt Quick Ultralite（Qul）及界面绑定痕迹。精确 MCU 芯片料号尚未确定。

主机通过服务属性、D-Bus、中继程序及 UART 与 exMCU 交互，MCU 再由本地 Qul UI 驱动 LCD。原厂初始化配置描述的串行速率为 460800。它不是主机将完整后屏图像缩小发送到肩屏的架构。同份 MCU 固件也处理按键、电源、电池、镜头、曝光及 IBIS 相关事务，不能把其职责限定为显示。

## 可以辨认的显示状态

| 类别 | 静态证据与可辨认内容 |
| --- | --- |
| 曝光 | ControlScreen 参数与 source/value 绑定，光圈、快门、ISO、Auto ISO、曝光模式图标 |
| 测光 | balanceScale 的 value/valid/visible 绑定及主机测光平衡属性发送体 |
| 白平衡 | 模式图标、选择列表、色温叠层与相关属性转发 |
| 电池 | 电量条、充电图标、大电池页面和文本；部分状态在 MCU 本地获取 |
| 存储与处理 | 剩余张数、忙碌动画、待处理计数与相关主机属性 |
| 拍摄过程 | 自拍、长曝光、间隔、曝光包围、焦点包围、进度文本及图标 |
| 系统状态 | 存储连接、关机、休眠、电池缺失或耗尽、亮度及校准状态资源 |

这是编译后界面和协议痕迹，不是本轮逐项实机验收。接收某个属性不保证肩屏显示该值：部分属性可能只供 MCU 控制使用。

## 潜在额外界面与边界

MultiShot 是有较强静态连接证据的额外状态：MCU 中有 multishot、exposeScreenState、exposureCounter、progressText、progressIcon，主机对应的曝光计数发送体也已定位。因此不能把它称为“UI 已写好但完全没接线”。真实模式许可、完整拍摄序列、肩屏进入条件与成片效果仍未在本研究中验证。

白平衡资源包含 tempTint 绑定与 WbTempOverlay，但已查属性和中继中未见独立 tint 字段。没有恢复完整 MCU 数据流，尚不能断言它是未接通的成品功能。

本次库存未找到足以确认肩屏已有直方图、水平仪、实时画面或对焦距离界面的证据；这不是全固件不存在这些能力的证明。新增消息值也不会自动生成新的肩屏布局。

## 证据范围

主要依据为原厂初始化配置、带偏移的 MCU 字符串与绑定名、主机符号及测光/MultiShot 两处发送函数反汇编。该架构调查本身没有完成全部 MCU 界面的 Thumb 数据流恢复；后续[校验专题](CONTAINER-VALIDATION.md)的函数级分析不能被扩大成全部界面都已反编译。原始资源、脚本、反汇编与设备记录不随本文公开。
