# 原厂 ION 句柄租约隔离测试

适用：X2D 100C 4.2.0，来源函数来自该机原厂 `dji_ml` / `libduml_hal.so`。当前版本测试一代 HAL 的 4 KiB 自建缓冲区能否通过原厂共享句柄接口再导入、核对大小，以及释放原句柄后导入句柄能否保持有效；**不接取景帧、二代模型、追踪、AF 或 GUI**，不能据此宣称完整移植。二代 1.3.16.2 原厂 DSH 回调会导入 `frame+0x70` 的句柄，是本测试的研究动机。

`ion_lease_probe.c` 与 `ion_cross_process_probe.c` 是接口胶水的独立验证程序，不包含识别或追踪算法。前者验证同进程释放后的寿命，后者让一个全新执行的进程重新打开原厂 HAL，导入发送进程的共享句柄，且在发送端释放后再次查询大小。它们动态加载机身已有的原厂 `libduml_hal.so`，使用第一代原厂程序观察到的 `/dev/ion` 初始化及 4 KiB 分配参数。第一轮实机发现仅传入设备名不足以注册 ION；随后查明原厂 `dji_ml` 的初始化表在 `+8/+0x10` 通过 ELF 重定位填入 `duss_hal_attach_ion_mem`／`duss_hal_detach_ion_mem`，现按该原厂表补齐。失败时由隔离进程退出关闭其 ION 描述符；不打印物理地址或共享句柄。其函数签名来自固定 ELF 指令推断，尚无原厂头文件；错误签名可能导致**隔离进程**崩溃，因此必须限时运行，不可加载到 `camera-service` 或 `dji_ml` 进程。

依赖：Android ARM64/API 28 编译工具链，及机身原厂库。固件未随仓库提供。构建输出仅放临时目录；仓库默认不附带二进制或自动上机脚本。即使自建内存测试通过，仍须另行验证真实帧字段含义、目标缓冲区大小、缓存同步、并发和异步消费者完成后的释放。

设备副作用：单独进程短暂打开 `/dev/ion`、分配 4 KiB、导入和释放句柄；不写系统分区、不更改 AF、相机服务或持久 USB 配置。实机执行前必须核对机型/固件/原厂 HAL 哈希，以独立计时器限制运行并在退出后检查服务、USB 与临时载荷清理。仅编译或检查 ELF 不连接相机。

离线复核表明旧程序把 `duss_hal_mem_get_phys_addr` 的输出交给 `duss_hal_mem_import`，但原厂 HAL 同时提供独立的 `duss_hal_mem_share` 和 `ion_custom_export_share_handle`／`ion_custom_import_share_handle` 路径。固定版 HAL 的导入后端 `0x278c8–0x27954` 根据句柄低十位选择不同分支；把通常对齐的物理地址送入这里，会走 `0x2792c` 的编码值解包分支，而非 `0x278d4` 的共享句柄导入分支。这已证明旧测试的传参假设错误；`get_size` 失败及退出码 138 的全部具体触发点仍未确定。

修正版改用一代原厂 `duss_hal_mem_share`（固定 HAL 表 `+0x48` 指向 `0x277e8`，读取内存对象 `+0x40`）产生句柄，再传给 `duss_hal_mem_import`（表 `+0x50` 指向 `0x27888`）；若低十位不符合共享句柄分支，立即停止。进一步确认两代原厂 `dji_ml` 都以 `mem_free(handle)` 而不是 `mem_free(&handle)` 调用释放接口，修正了旧探针的第二处 ABI 错误。当前探针在成功路径释放原句柄、核对导入句柄大小不变，再释放导入句柄；失败路径则依赖独立进程退出关闭 ION 描述符。执行入口拒绝旧包或与当前源码哈希不一致的包。

修正版实机验证前两轮：原厂 X2D 4.2.0 HAL 的 4 KiB 自建缓冲区 `share → import → get_size` 通过；同进程 `share → import → 释放原句柄 → 再查导入句柄大小 → 释放导入句柄` 也通过，均退出码 0。用户确认这两轮后取景、菜单、55V 镜头正常，无闪烁、卡顿或调试选项残留。
