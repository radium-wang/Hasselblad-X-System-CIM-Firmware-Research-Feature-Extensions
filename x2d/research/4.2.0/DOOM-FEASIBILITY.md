# X2D 100C 运行 Doom：实现与验证边界

更新：2026-10-07。对象仅为第一代 X2D 100C，固件 4.2.0 / build 24849。源码入口为 [Doom 模块](../../doom/README.md)。本文只保留结论、版本与脱敏指标；没有原厂固件、WAD 或原始设备日志。本次开源整理未连接相机。

此前有声实机样本包含 `audioFrames=3504128`、`audioNonzeroFrames=23026`、一次快门开火及弹药 50→49。这些计数说明对应试验过程中音频环和输入链工作，不代表听感质量、屏幕 FPS、延迟或完整通关。本次公开源码补齐本地构建器、USB 依赖、来源绑定和 GUI 启动前存活门禁，不能凭旧试验宣称修改后的运行器已实测。

## 平台与显示路线

离线检查确认 Android API 28、ARM64-only、Qt 6.4.1 与 Wayland。Qt Quick 编入原厂 GUI；没有可直接依赖的独立 Qt6Quick 动态库或 SDL。BMP 读取器和多点触摸接口存在，适合从独立引擎输出像素，再由原厂 Qt 显示。

引擎是 AArch64 静态 musl 程序，内部 320×200 帧写入专用 RAM 的原子 BMP 文件。QML 按 4:3 显示，提供触屏控制和退出。输入文件含递增序号、按键掩码、快门计数、累计转向量及格式标识。滑动转为真实 Doom `ev_mouse` 水平事件；单次差分有界，松手后没有惯性转向。

MainScreen 通过离线生成的被动 Loader 接入。原单元 15084 字节，生成器保留函数/对象布局、AOT 关联及相邻边界；运行器核对目标进程的原始 RAM 哈希后才替换这一个单元。生成后的单元仍含原厂字节，只供使用者本地实验，不进入开源仓库。没有把磁盘固件改成游戏系统。

## 快门与焦点

`KeyHandlerX2d` 将全按映射为 Qt `Key_E`（69），半按为 `Key_A`（65）。路由枚举为 0 None、1 Listen、2 HalfOverride、3 Override。静态检查原厂 `camera-service` 分支确认 mode 3 避开原厂半按/全按回调。

页面使用原厂 `keyOverride=3`，只有焦点正确且服务返回模式 3 时才接受快门。不是把收不到原厂响应当作接管成功。半按与按键自动重复被忽略；完整按下计数用于保留短按脉冲，仍遵循游戏枪械冷却。隐藏、失焦、退出与输入心跳过期会释放键。

静态分析定位了持键退出时原厂路由延后清除的分支，但“持快门点 EXIT 后绝不触发拍摄”没有专门实机验收。原先关于 InputEventFilter 总会吞掉活动画面按键的猜测，经分支核对已纠正。公开 `audit_shutter.py` 默认校验 14 条关键指令；可选 ARM 仿真不包含真实相机回调，本次也未通过原生 Unicorn 初始化。

## 音频路线

`doom_sound.c` 从使用者 WAD 读取 DMX 效果，检查格式、采样率、长度及边界，缓存上限 16 MiB，最多 16 声道，线性插值混到 48 kHz、16-bit 双声道。PCM 走带 acquire/release 的共享 RAM 环，独立音频桥消费后调用原厂 `libaudioclient.so`。音乐接口未实现，运行命令使用 `-nomusic`。

桥以试验专用 `LD_PRELOAD` 启动在独立原厂 sleep 进程中，仅在环境标志匹配时工作。使用原厂扬声器服务和单流音量，不改设备全局音量。正常退出路径关闭 stream/device；代码存在不等于实机关闭已验收。

SELinux 策略未修改。此前试验发现默认 tmpfs 标签不适合该输入桥，数据 RAM 改用 `rootcontext=system_data_file`；音频代码 RAM 使用 `rootcontext=system_file`。尝试对数据文件直接改成 vendor 标签被拒绝，该失败试验已回退，公开运行器不包含这条重标记路径。

## 临时运行与恢复

运行器默认不访问设备。`--apply` 才 claim 已有 USB interface 3，经固定命令临时开启 ADB、暂存本次引擎/WAD、挂载 RAM 并重启原厂 GUI。读回机型/build、原厂文件哈希、拍摄空闲、输入路由、USB、空间是启动门禁；GUI 停止前还核对监护、引擎、音频存活与退出标记。

监护先于 GUI 停止启动，配置上限 30–180 秒，包含准备时间。EXIT、进程死亡或到期后执行恢复：释放路由、终止带试验环境标记的进程、重启原厂 GUI、卸载试验 RAM、清理暂存、恢复原 USB。卸载失败时保留目录，避免删除挂载内内容。模块没有持久启动入口、不修改 `/system` 或 init 文件。通信异常、竞态与断电情况下不能保证完成恢复。

静音阶段已有完整恢复读回；有声阶段仍需要实际读回音频流关闭、服务与 USB/路由恢复、试验进程退出和挂载/暂存清理。不要将独立监护的设计写成已完成全部故障验收。

## 本次公开源码的离线验收

- Clang 桌面引擎、Zig 0.13.0 AArch64 静态引擎与原厂 ABI 音频桥构建通过；动态导入都存在于精确输入库，无可写可执行段。
- Qt 6.4.1 实际事件测试通过：全按/快速短按弹药减少、半按无效、重复忽略、滑动改变玩家角度、双指移动与转向、松手停止、心跳清键及 EXIT。
- PCM 消费器观察到至少两次音效启动、非零采样、错误计数为 0；这是电脑捕获，不是本次相机扬声器测试。
- 相机服务替身验证路由确认、路由丢失清键、焦点返回和单覆盖层；没有 QML warning。
- 合成 USB 检查覆盖 CRC 标准向量、长度/NUL 限制、逐字节分片、噪声/坏帧、旧 cookie、非零状态、超时、不重试执行与资源释放；测试不导入 PyUSB。
- 精确原厂平台/快门静态检查、本地打包、生成 shell 语法及 launch/status/restore 默认计划通过；源码/WAD 绑定防止旧桌面验收被用于另一份载荷。

源码许可、固定上游和复现命令见[模块 README](../../doom/README.md)。没有测量屏幕 FPS、热、续航、音频端到端延迟、完整游戏兼容、长期运行或跨机型适用性。
