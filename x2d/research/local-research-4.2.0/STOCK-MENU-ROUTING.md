# 原厂主菜单结构与子页面生命周期

依据官方 X2D 4.2.0 `camera-gui` 的资源、符号、元对象表及反汇编，哈希见索引。以下为静态证据与桌面原型结果；尚未完成原厂菜单集成部署。

## 网格、模型与路由

`MainScreen.qml` 的非稀疏网格为三行四列，数据来自 `viewModel.favoriteModel`。图标、名称、可点状态及菜单标识都来自模型；绘制第十二格本身不等于接入原厂菜单。

`FavoriteModel::init` 位于 `0x1050a20`，从每条 32 字节的顶层菜单记录构建项目。内部 `FavoriteModel::addItem` 位于 `0x1050ba8`，但该类自身的 Qt 元调用入口只分派 `onImageFormatChanged`、`reloadModel`、`count`、`itemEnabled`，没有把 addItem 暴露给 QML。

点击经 `loadSubMenuItem` 进入 MainMenu 路由。`MenuX2d::menuFile` 位于 `0x358ca0`，未知菜单名返回空字符串。因此既要解决新图标，也要解决真实页面入口。

MainMenu 在加载子页前检查媒体处理状态，并处理页面参数、焦点和退出按键。关闭菜单的调用还可能用于回取景等行为，不应全部改成再次打开自定义菜单。

这些结构长 24 字节，原始第三字段为零。存在可定位指针不代表能任意替换；仍需核对函数表兼容性、类型、引用生命周期与对象创建时序。

## 常驻子页面

原厂 HblLoader 同时观察 source 和 active；加载条件不满足时清空内部 Loader.source。MainMenu 返回时也清空来源，因此这条原厂路径本身不保留子页实例。

本地原型采用直接创建纯 UI 引闪页、通过显隐保持对象的容器，由适配层提供菜单激活、媒体处理忙、原厂子菜单激活三个状态。

桌面 Python 3.11 / Qt 验证记录：默认隐藏；忙状态拒绝打开；实际 Escape 先退详情再退引闪页；100 次往返底层页面对象保持同一个，本地草稿保留；退出主菜单隐藏，重新进入不自动弹回；最终无 QML 警告。

此验证没有相机或无线操作，不覆盖原厂按键处理、真实模型注入、设备合成显示、AF-C 后端或开机性能。本批只共享研究结论，原型源码和可移植依赖尚未整理进本目录。
