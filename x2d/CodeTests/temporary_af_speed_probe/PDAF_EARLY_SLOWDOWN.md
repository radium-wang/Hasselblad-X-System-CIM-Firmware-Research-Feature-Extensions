# X2D 4.2.0：提前降档条件的静态核对

本轮只读原厂固件，没有访问或修改相机。输入 `/lib64/libaaa.so` SHA-256 为 `feef8a8dc3a27395e47232c2b25a5da7a7ab335922fbb527e637c439e35bcec7`。

## 新结论

已找到基于剩余距离和最近位置变化的提前降档分类，不是固定的减速毫秒数。分类还与光学距离阈值取或关系。当前相机运行参数、使能状态和实际使用路径尚未回读。

## 分类函数

`get_pdaf_distance_to_peak`：`0x927b0`，812 字节。

令 P 为传入的峰值参考位置，C 为当前位置，L 为上次位置：

```
D = abs(P - C)
delta = abs(C - L)
K = lens_ctrl_get_steps_per_fdelta_double(...)

若启用／状态门槛未通过：返回0
否则若 D < N_super * delta：返回2
否则若 D < Q_super * K：返回2
否则若 D < N_close * delta：返回1
否则若 D < Q_close * K：返回1
否则：返回0
```

所有距离比较为严格小于。函数取得当前帧率并计算 `delta * fps`，但在这段函数中该乘积用于日志；分支实际比较使用的是位置差乘帧数系数。因此不能把它写成“速度乘固定毫秒”并当作原代码。

N_super、N_close 分别在模式参数块 +0x00、+0x08；Q_super、Q_close 分别在 +0x10、+0x18，均为 double。+0x28 的 byte 必须非零且传入的第三参数按 signed byte 解释后大于该值，才进行分类。第三参数的完整语义还未核对，不能擅自叫相位置信度。

原厂日志明确把两类描述为 peak super close / close，并分别说明按当前速度若干帧内到达、或处在若干 fDelta 内。这支持提前降档解释，但不是物理制动距离模型的证明。

## 参数来源

`af_get_pdaf_af_mode_params` 的真实入口 `0xb1088`，根据模式选择三个 0x30 字节块，返回基础参数 +0x980／+0x9b0／+0x9e0。本轮只核对选择逻辑，没有读取本次相机中的阈值数值。

## 分类到速度的消费路径

`_exec_pdaf_afs_process` 在 `0x904c4` 和 `0x905ac` 调用上述分类函数，并在 `0x904d4`、`0x905bc` 通过 `alg_set_distance_to_peak` 存储分类。

`cdaf_get_scan_speed_type`（`0x574e0`）读取分类；当分类非零且 `af_get_cdaf_special_param` 返回结构的 byte +0x32 非零时，直接调用 `get_speed_type_from_peak_distance`：拍照分类1→Type1，分类2→Type2。这个分支提前返回，不经过下面的提速等待计数。

不能把分类0简单理解为所有情况下直接使用Type0：分类为0或使能关闭时，还会进入清晰度指标和当前档位的选速逻辑。

## 另一条清晰度选档及等待

分类未直接决定档位时，该函数读取最近三次清晰度指标，比较相邻变化比例与 special param double +0x28。拍照条件下可选择Type0或Type1。

若新档计算出的速度高于当前速度，且 special param ushort +0x30 非零，函数用工作帧计数等待达到配置值才允许提速；新速度不高于当前速度时清除提速等待，不经这个等待再降档。这是提速等待，不是减速时间。

## 对提速修改的意义

只看此分类公式，位置变化 delta 增大，会扩大 `N * delta` 对应的提前降档距离；光学阈值 `Q * K` 不会仅因速度倍率变大自动改变。原厂已考虑最近运动量，但不能由此推断此前三档倍率必然不会冲过焦点。

限制：该分类必须被写入并由启用的消费路径读取；其他相位分支会清零分类，且两处原厂方向扫描仍固定请求Type2。方向／位置切换、实际马达减速度、通信延迟和取消停止链仍需分别核对。

补充更正：`cdaf_get_scan_speed_time` 的函数起点是 `0x569d8`；`0x56b34` 是它内部调用速度计算的指令地址，不是函数入口。该函数没有输出减速时间，名字中的 time 不能当作证据。
