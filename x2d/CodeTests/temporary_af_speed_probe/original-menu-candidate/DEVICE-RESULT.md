# 原厂菜单接入：临时验收与开机配置记录

对象：第一代 X2D 100C，官方 4.2.0 精确 GUI 构建。用户本轮明确要求实机接入，并最终开机持久加载；临时试运行是验收阶段。

> 当前源码保留主菜单 + AF-C 菜单的组合挂接，但已把第十二格的活动页面从“引闪”替换为“耍起功能”。下文的引闪页面验收和冷启动记录均属于历史已安装版。新的“耍起功能”临时版已于 2026-09-25 通过实机菜单/页面/退出验收并完整恢复；它没有进行开机常驻安装或 AF-C 后端跟焦验收，详见 [新实机记录](LIVE-DEVICE-TEST.md)。

## 已验证

- 原厂 MainScreen 编译单元副本增加一个 Loader，原函数表、原对象索引和原有绑定保留。桌面 Qt 6.4.1 已实际加载该编译副本，不只是解析文件。
- Loader 自动创建 Bootstrap，延后断开 ControlDrawer 原本的具名点击连接，再接入扩展分派。原厂十一项原样转发，第十二项消费于自定义引闪 UI。
- 桌面打包文件验证通过三十次真实点击/返回，包含 Escape、原厂关闭信号和退出主菜单信号；实例保持，状态与横向滑动门控恢复。撤回时必须同时恢复原模型与原 delegate，已修正并验证。
- Android/AArch64 加载库已构建，导入与固定固件 libc/libdl 对照通过；没有可写可执行段。启动前检查精确原单元字节、缓存指针和显式启用变量。禁用文件可使其不挂接；同次开机第二次进程启动默认跳过扩展，避免候选导致无限重启。
- 扩展库与十一份 QML 文件已安装到现有 `/system/lib64/`、`/system/etc/` 中；文件逐一回读校验通过。未改原厂 `camera-gui` 文件。
- 当前临时 GUI 候选存活，模块状态为 `BOOTSTRAP_POINTER_READY`。这是缓存指针接入成功，不等于菜单已显示或触控已验收。
- 旧独立预览已正常暂停并恢复原实体键映射。候选通过维护域启动；监督脚本在候选进程退出时恢复 init 原厂 GUI 与旧预览服务。
- 系统分区已恢复只读，临时 USB ADB 已自动关闭。
- 用户已实机确认：原厂菜单出现“引闪”，点击能够进入引闪页面。此确认不包含返回、半按退出或冷启动验收。
- 随后执行带原配置和模块哈希检查的开机配置事务，返回 `ORIGINAL_MENU_BOOT_CONFIG_INSTALLED`。两份配置与备份均逐一回读匹配，系统恢复只读；当前临时 GUI 进程未重启。

## 安装中遇到的实际限制

第一次安装尝试在新建系统目录时被拒绝；安装事务执行清理并恢复只读，没有覆盖原厂文件。随后改为现有目录内的独立命名文件，安装成功。未修改安全策略或开启其他测试模式。

桌面 Python 回调直接参与 Qt 类型加载曾发生等待问题，已结束该本轮桌面进程，改用原生桌面回调桥，随后编译单元验证通过；没有相机进程因此受影响。

## 当前尚未完成

原厂入口与进入页面已经由用户确认；仍待返回、半按退出和冷启动验收。当前旧前键自定义绑定已暂停，应使用**原厂菜单键**，不能用旧独立页面证明原厂集成成功。

`native-package/activate-boot.sh` 已执行；`restore-boot.sh` 已与安装配置一同放到机内暂存目录并校验，尚未执行恢复。开机配置已持久写入，**不等于冷启动已经通过**。

本次仅给原厂 GUI 服务增加两个环境变量，关闭旧独立预览的自动启动触发、保留其手动撤回服务。两份原配置已按哈希备份与回读，原厂 GUI 可执行文件未修改。该方案每次开机首次 GUI 启动构造运行时扩展，不保存上一进程内存地址；同次开机后续 GUI 启动跳过扩展以防循环失败。

上述首次版本没有接入无线发射、镜头、曝光或 AF-C 功能。机内菜单显示与点击进入已经用户确认；半按、休眠、返回与冷启动性能尚未验收。桌面外层状态和图形替身不代表这些项目已通过。

## 后续：高亮修正和 AF-C 弹窗候选

用户报告点击引闪时高亮沿用上一个按钮。本地真实原厂 delegate 测试复现：未解析扩展项的源模型索引无效。Bootstrap 对第十二项的 pressed 信号补充实际显示索引，沿用原厂高亮函数；新增按下阶段的索引断言，三十次往返与全部原项目检查通过。

用户进一步要求参数页对焦模式弹窗加入 AF-C。只读引用共享仓库的两份生成函数，从精确 4.2.0 原始单元重新生成 ControlScreenViewModel 三项模型和 PopoverFocusMode 三项布局；生成哈希与参考记录一致。原有函数字节与索引保留。组合模块同时挂接主菜单、对焦模式模型和弹窗布局，并启用 canChangeAfc；不会主动改变当前对焦模式、触发对焦或拍照。

ARM64 构造器离线模拟通过十二个场景：正常挂接、未启用、禁用标记、重复启动、模型/布局/门控不符、打不开进程内存，以及四处写入分别发生短写后的逆序恢复。此结果不等于实机连续对焦验收。

第一次原子文件更新后的 remount-ro 报 busy，更新文件已退回旧版，但分区暂时仍可写。正在运行的库被替换后成为无目录链接的映射，是此次安装必须处理的问题。随后用户已手动重启；回读确认只读、旧版本正常加载。硬链接保留旧映射方案被设备权限拒绝，未因此改变策略。最终在精确核对并停止原厂 GUI 后更新两份文件，恢复只读，再由 init 启动 GUI。更新返回 AFC_UPDATE_INSTALLED_READONLY，两个文件回读符合 afc-update-manifest.json。

另外发现启动目录内仍保留了带启动动作的历史备份，旧独立菜单开机仍运行。四份备份已按哈希迁移到 /system/etc/X2dBackup-*，保留数据并移出 init 扫描目录；用户随后那次冷启动只运行原厂 GUI，旧预览未启动。开机配置生成器已修正备份位置。

安装后的同次 GUI 重启状态为 SKIPPED_RETRY，属于保护性跳过。随后用户再次完整重启；本轮冷启动回读为 MENU_AND_AFC_POINTERS_READY，init 原厂 GUI 正常运行，只有一个 camera-gui 进程，两份更新文件哈希匹配，系统只读、USB ADB 停止，旧独立预览没有启动。**组合模块已通过一次冷启动挂接，但 AF-C 弹窗显示、选择后的实际跟焦，以及高亮修正的视觉效果仍待用户验收。** 不能仅凭挂接标记声称实际连续对焦已可用。

恢复方案：restore-afc.sh 已修正为先停止 GUI 再替换，避免映射文件替换造成只读恢复受阻；restore-boot.sh 使用目录外备份。旧的 update-afc.sh/Recover-AfcUpdate.ps1 是本轮失败与恢复尝试的记录，不作为当前安装入口。当前安装证据对应 Install-AfcUpdate.ps1 生成的已停止 GUI 后更新版本。

修正后的 restore-afc.sh 已通过维护通道放回机内暂存目录，语法检查与主机/机内哈希一致；没有执行恢复。
